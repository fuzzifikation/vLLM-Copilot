# Licenses

This repository is dual-licensed, and this folder is the single source of truth for both texts.

| File | Applies to |
|---|---|
| `LICENSE-BUSL-1.1.txt` | the source repository: the code, the git history, the Marketplace listing |
| `LICENSE-MIT.txt` | the distributed VSIX: what an installed copy of the extension is licensed under |

`package.json` declares `"license": "MIT"`, because the thing users install is the MIT-licensed extension. The root `LICENSE` file is the BUSL-1.1 source license, and the two must not be confused: shipping the source license to end users would be the wrong license for the artifact, and committing the MIT text to the root would mislicense the source.

## Why the root file is not the source

`npm run package:vsix` needs VSCE to see an MIT `LICENSE` next to the MIT manifest, and VSCE reads the license from the working directory. There is no flag to point it elsewhere: the only license-related option is `--skip-license`, which drops the license from the package entirely.

An earlier version therefore wrote MIT over the root `LICENSE` for the duration of the package step and restored BUSL in a `finally`. That covers a clean exit and a thrown error, and nothing else. A hard kill left MIT at the repository root, and repairing it on the next packaging run does not help a commit made in between: the wrong license ends up in permanent history.

So the root file is never written at all. The working tree is copied to a temp directory, the three shipping dependencies are copied in, the MIT license lands in the COPY, and VSCE runs with its working directory inside the copy. A killed run leaves an orphaned temp folder and nothing to repair. The root `LICENSE` is a plain tracked BUSL file; if it differs from the canonical text, packaging stops without changing it, including on worktrees left by the old implementation.

The copy is a copy of the tree rather than a hand-maintained file list, so `.vscodeignore` stays the only thing that decides what ships. The staged manifest drops the `vscode:prepublish` hook, because that hook cannot run in a copy holding no development dependencies; the wrapper runs it in the real tree first, so `out/` is always fresh. That is the one difference between the shipped manifest and the repository one, and it is inert metadata that VS Code never executes on an installed extension.

Both texts are verified (BUSL-1.1 and MIT markers) before anything is written, so a wrong or truncated file in this folder fails the build rather than reaching a package.

## Editing a license

Edit the canonical text here. For a source-license change, update the tracked root `LICENSE` deliberately to match; packaging refuses a mismatch without overwriting local edits, and the license test detects it.

Neither text may appear anywhere else in the repository. `THIRD-PARTY-NOTICES.txt` covers dependency licenses separately and is generated by `npm run license:notices`.
