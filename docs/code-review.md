# Live Issues

**House rule (the only permanent thing in this file): this is a collection of LIVE issues.** A finding that gets fixed **leaves the document**. No "status after fix pass N" section, no "fixed by CR-n" annotations, no archive, no grade, no victory lap. Git history holds the record; the CHANGELOG holds the user-visible slice per its own policy. We do not collect fixed issues here, because nobody reads what was already done and the file would end up the size of War and Peace.

Two exceptions stay, because they are still live work:
- **Rejected findings** (bottom). A rejection is a standing decision, not a fixed bug: it stops a future review re-filing the same dead idea. Keep those.
- **Accepted product decisions and deferred architecture.** Same reasoning: standing rulings.

When you fix something, delete its entry in the same commit. If a fix was a partial amputation, rewrite the entry down to whatever is genuinely left, and drop stale line numbers while you are there (they rot within hours). Do not bump version without asking. Write prose as one line per paragraph or list item, no hard wraps, the editor does the wrapping.

## Accepted product decisions

- **Raw headers in opt-in local logs/diagnostics** - intentional, user-controlled, stays on the user's machine.
- **`scope` and `wording` in prompt-replacement files are dev-only metadata** - enforcement lives in `check:copilot-rules` and `test/copilotPromptRules.test.ts`, not runtime. The loader drops both.
- **Two harnesses, one prompt wording each (owner ruling 2026-11-10).** The **Local harness** (VS Code main window, rules with no `scope`) and the **Copilot harness** (Agents window / Agent Host, rules with `"scope": "copilot"` - the surface the code called "CLI") each ship their own prompt, and presets anchor the CURRENT wording of each: Copilot-harness rules bound to specific text carry `"wording": "sdk"`, untagged ones anchor boilerplate every wording shares. When Microsoft renames a prompt, re-anchor the affected rules and regenerate `scripts/copilot-prompt-reference.txt` in the same commit - do NOT keep both wordings as rule pairs "so older VS Code keeps its personality". The cli/sdk twin scheme existed for about an hour and was ruled out the same day. Consequence accepted: a user on a superseded harness gets vanilla identity until they update. Rule *names* keep their historical `(CLI)` suffix - renaming prompt-adjacent labels invites blind text substitution; the vocabulary lives in `scope`, the docs, and the tooling.
- **Local-harness prompt rules are on a clock (VS Code 1.146, 2026-11-11).** Microsoft deprecated the Local harness and dates its removal to February 2027, and new chats have defaulted to the Copilot harness since 1.143, so untagged (`Local`) rules now cover only sessions the user switched by hand. Do not add new untagged anchors; when Local disappears, those rules and the Local half of `check:prompt-drift` go in one commit. Facts: [agents-window.md](./agents-window.md#which-harness-runs-your-chat).
- **Server registry** - entry id is the identity unit; models only reference an entry via `server`; no global/default server.
- **URL-wide fan-out for Update Auth and Rename pre-flight** (§5); entry-addressing stays for Replace Config and Remove Server.
- **Usage keyed by URL, not entry id.**
- **Cross-window `settings.json` writes are whole-array read-modify-write with no MVCC**; every in-window path re-reads at write time; the cross-process race is the platform ceiling.
- **The bundled model schema keeps `required: ["id", "server"]`.** Migration orphans are a warned, self-healing transient; blessing them in the schema would hand Copilot's `vllm-copilot_model_schema` tool a contract that tolerates broken entries. The editor squiggle is the feature.
- **Optional persistence failures stay Output-channel-only.** Chat continues safely; the data is optional.
- **Keys in plain-text settings.** Project decision, recorded so reviews stop filing it: plaintext beats secret storage for this use case. Never surface it as a finding.
- **Cost is USD only (ruling 2026-09-25).** No second currency is reachable from any UI, and none should be added. The retired `AI Credits` option existed to price a model in the same unit as the Copilot picker (1 credit = $0.01), but that is a Microsoft billing unit, not a currency: OpenRouter uses the word "credits" for a prepaid *dollar* wallet and Cursor for a seat quota, and no inference provider denominates per-1M-token rates in credits. Every rate in this product is dollars, and the picker comparison is arithmetic the user can do. The raw-label fallback in `currencyPrefix` stays on purpose — a pre-ruling `settings.json` carrying `currency: "AI Credits"` must render that literal, never a wrong `$`. Do not re-file currency support.
- **`style-src 'unsafe-inline'` in the webview CSP** (ratified 2026-09-25). All three shipped webviews set element styles directly at runtime, so the exception is deliberate. `script-src` stays locked to `${cspSource}` with no `unsafe-inline` or `unsafe-eval`, which is the part that actually matters. `.github/copilot-instructions.md` now documents the exception; do not re-file this and do not refactor inline styles into CSS files to chase it.
- **Configured `contextWindow` must be a whole number above 50,000** (`isValidContextWindow`). Intentional floor, ratified 2026-09-10 after an external review filed it as "rejects valid 32K gateways": below ~50k Copilot has no usable prompt+output headroom, so the manual fallback refuses to relocate the failure. The asymmetry with server-reported windows (any positive value) is the point - the server's number is authoritative, a typed guess is not. Do not re-file.
- **`check:prompt-drift` red on upstream SHA drift is expected noise until re-pinned.** The canary watches `microsoft/vscode` prompt sources; when upstream moves, the script exits 1 by design until a human re-verifies the rules against a fresh `systemMessageCapture` and runs `--update-baseline`. That re-pin is a deliberate human ritual, not a bug and not CI's business. Know what each half can see: the canary's Copilot-harness arm compares rules against `scripts/copilot-prompt-reference.txt` - a frozen capture, so it proves presets and reference agree and proves NOTHING about the live prompt (a stale reference matched against stale rules reads as "All good" forever). `check:copilot-rules` against a fresh capture is the only instrument that can see harness drift, which is why its harness detection lives in `scripts/copilot-prompt-wording.mjs` and anchors on wording that survived the 2026-11 "Copilot CLI runtime" → "Copilot SDK" rename. Run it after any Agents-window session.

## Prioritization rule

**wrong behavior -> dishonest failure classification -> duplicate authority -> misleading API/tests -> measured performance cost -> structural cleanup.** Keep each change tied to one observable invariant. Do not refactor merely because a file is large; refactor when ownership can be stated more clearly afterward and protected by a focused behavioral test.
